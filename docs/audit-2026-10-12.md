# UpdateBar reliability and performance audit — 2026-10-12

Implemented changes:

- Shared refresh tasks prevent duplicate scan work. Preference changes and
  completed installations request a follow-up scan, so an older in-flight result
  cannot overwrite current state. Diagnostic reports do not notify or modify
  notification history; command-line Sparkle installs honor beta preferences.
- One reservation covers app batches, single app installs, and Homebrew tool
  installs. Repeated clicks cannot start competing installers. Late progress
  callbacks are ignored after their action finishes.
- Decoded Homebrew models are reused for the remainder of the existing ten-minute
  freshness window. Concurrent callers share one load. Downloaded JSON is
  validated before replacing a good cache, obsolete ETags are removed, and stale
  fallback results include a warning.
- Homebrew's exact architecture/macOS variations are merged before evaluation.
  Only the installer's Homebrew prefix is scanned. Installed app ownership uses
  resolved Caskroom artifact paths; uninstall IDs may name helper processes.
- Sparkle selection honors operating system and maximum/minimum macOS, ignores
  nested delta enclosures, and rejects malformed partial feeds. HTTPS redirects
  cannot downgrade to HTTP.
- App icons are cached outside view body evaluation. Hiding command-line tools
  skips their scan. Incomplete checks do not show a clean up-to-date state, and
  successful tool-upgrade notices are rendered.

## Measured index loading

`./script/benchmark_indexes.sh` compares uncached decoding with the new in-memory
path using the same local copy of Homebrew's public indexes. It does not contact
servers or install anything. Final fixture size: 50,941,639 bytes; 4,201 casks and
8,658 formulae.

| Operation | Observed elapsed time |
| --- | ---: |
| Three uncached decode passes | 1.3965 seconds |
| One cold cache load | 0.4596 seconds |
| Three warm cache loads | 0.000065 seconds |

This measures index processing only. It does not establish an equivalent speedup
for a complete scan, network requests, or UI interactions. The cache does not
extend the original disk-cache freshness window.
